# Keep the work resumable

Keep task notes and receipts in the conversation or a user-requested document. When the host offers
file storage, a production directory outside the installed plugin may be used. Local filesystem access
is optional. Keep user media, generated outputs and credentials outside this reusable package.

Keep these responsibilities visible; combine notes for a small commission:
- Brief: goal, audience, deliverable, inputs and roles, locked requirements, assumptions and generation scope.
- Reference analysis: inspected sources/ranges, observations, uncertainties and relationships to transfer.
- Product ledger: SKU/appearance locks, claim evidence, approved wording and brand assets.
- Treatment and sequence: creative reasoning, shot responsibilities, words, graphics, timing and sound.
- Progress: accepted selections, active tasks, failed attempts, review findings and the next action.
- Receipts and delivery: exact prompts/settings/references, task IDs, output paths and selected variants.

Choose useful filenames rather than inventing a mandatory production format. A small project might use
notes, sources, prompts, receipts, outputs and review folders. For each asset, retain its origin, role,
selected range, reference ID, generation lineage if any, accepted state and usable local path or URL.

On continuation, inspect conversation progress, accessible outputs and remote receipts before submitting work.
A missing final selection does not imply generation never happened. A lost observer does not cancel a task.
Preserve prior versions and explain decisions that filenames cannot recover.

Keep source analysis, creative plans, submitted prompts and actual output findings distinguishable.
Use stable shot/request/variant IDs to relate them. Update records after a revision so the selected output,
not an abandoned prompt or rejected draft, determines the final delivery description.

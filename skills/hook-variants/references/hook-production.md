# Create the ad before varying its opening

## Build one complete argument

Start from the user's product, audience, objective and available images. Apply the Performance Ads
[creative direction](creative-direction.md), [product evidence](product-and-claims.md) and
[sequence writing](sequence-and-prompts.md). Choose the advertising treatment before writing variants.
A UGC treatment needs a lived-in situation, close friend-to-friend speech, a specific recommendation
reason and useful product handling; it does not become a recital of selling points because it is a test.
Professional explanations, demonstrations, comparisons and product-led treatments can also fit the brief.

Develop the full baseline script: hook, substantive body and appropriate resolution. These are narrative
responsibilities, not compulsory equal sections. Make the body deliver the opening's promise with supported
evidence. An uploaded reference is optional; product images and a short brief are sufficient to begin.
Read supplied product pages and inspect actual images before requesting the same information again.

## Design a replaceable opening

Usually budget about three to five seconds for the hook, adjusted to meaningful speech and action boundaries.
Choose a body entry that can follow every proposed hook. Avoid a pronoun, interrupted demonstration or
unfinished sentence whose meaning depends on one unique opening. Do not freeze the performer to create a
join; a motivated cut to a detail, reaction or complete next thought can establish it.

Describe the continuity shared by the base and replacements: accepted reference images, product/SKU,
presenter and voice character, wardrobe, setting, light, camera treatment, language and natural audio.
Describe each opening's different line, action and delivery separately. Reference reuse helps continuity
but does not guarantee the same face, pose, voice or physical state. Inspect actual media before acceptance.

Match the planned replacement interval and every hook's usable length to keep full duration constant.
Prompt timestamps are not exact cut points. After generating the base, measure its real hook ending and
body entry; use that evidence to implement the approved seam. A material change in script, visible action,
replacement scope or runtime returns to plan review before additional paid generation.

## Make a useful set, not a phrase library

Default to five finished versions unless the user specifies otherwise. H1 belongs to the base ad; H2-H5
are additional openings. Explore distinct audience-relevant attention devices such as a concrete question,
a recognizable friction, a visible demonstration or an unexpected supported contrast. Choose from the
product and body rather than assigning the same five categories to every brief. Every opening must earn
its payoff in the unchanged body. Do not add a new claim merely to make one hook more striking.

Keep the main message, product facts, offer, body and ending fixed. The whole opening concept may change
picture, action and speech together when that is the requested variable; do not mislabel it a wording-only
experiment. Broader variation is expanded scope, not permission to quietly change the body. A request for
new hooks authorizes proposing new hooks, not generating them unseen.

## Present the scripts and mode together

Before review, prepare the complete base prompt and complete standalone prompt for each additional hook,
plus the planned assembly. A future accepted base asset can have a named reference role until its real
media identifier exists; do not invent an upload ID or defer the creative prompt until approval.
The Script Plan is the readable view of that same version. Show:

- The full base script, shared body and ending, with every spoken and added on-screen word.
- Each hook's rationale, exact speech, visible action, caption/overlay wording and planned duration.
- The common body entry and replacement interval; what is generated and what will be reused.
- The no-BGM decision, voice/ambience continuity and proposed output ratio/duration.
- Proposed versions, output count, actual generation-request count, selected mode, necessary image
  dependencies, estimated credits when available and authorized retry limits.

A five-version set normally needs one complete base generation and four hook generations if the live
model supports each duration. Image preparation, duration limits, a base assembled from multiple requests
or retries can change that count; disclose the real plan and cost. Do not assume a three-second request
is available. If a longer take is required, plan natural handles and a complete usable opening. Never cut
off a line or speed it up just to meet the edit window.

Use [generation approval](generation-approval.md), with native question UI when permitted. For example:

"These five versions share one body and ending; only the opening changes, and none includes background
music. Which versions would you like to generate? We can use Seedance 2.5 Draft previews, or full quality
at the shown resolution and estimated credits. You can also revise any script first."

Default to Draft when mode is unspecified, but wait for approval of scripts and generation scope. When
high-quality delivery was explicitly requested, present the full-quality default instead. Reuse clear
prior authorization. Selecting only some hooks changes the scope; if H1 is not selected, the base remains
a production dependency unless the revised approved plan uses a selected hook as its base. Make any
generation of an unselected baseline dependency explicit rather than hiding its cost.

Proposing variations already requested by the user does not require a redundant offer to keep the old hook.
If revising supplied creative input beyond the requested variation scope, END the plan response with what
changed, why, and the explicit choice of revised script or exact original. Mode choice alone does not
accept that rewrite. Keep genuine verbatim/timing locks and the approved body intact.

## Generate, reuse, then finish

1. Generate the approved full base ad with no BGM, using the shared references and continuity plan.
2. Inspect the actual base, including speech, product identity, body entry, ending and absence of music.
   Retain the full video, accepted body range and useful boundary frames/audio references where supported.
3. Generate only approved additional hooks. Bind accepted base references through actual supported inputs.
   Factual binding and measured trims implement the plan; a new creative proposal needs review.
4. Choose each complete usable hook and join it to the same accepted body media. H1 is the base; the others
   are full assembled ads. Follow [assembly and seams](assembly-and-seams.md).
5. Review full exports and label versions. Keep successful variants if another fails; report missing
   versions and unresolved continuity instead of declaring the whole set complete.

Assembly and sound review also apply to Draft previews. For HD delivery, upgrade only selected eligible
generated assets through their actual available offer and authorization, then reassemble and review.
The composite is not itself a model-native upgrade resource. If upgrading is unavailable or needs a new
generation, explain that difference before spending again. Reuse one accepted full-quality body across
selected final versions; do not upsample Draft and call it an HD upgrade.

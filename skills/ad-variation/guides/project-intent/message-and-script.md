# Develop the message in sparse and detailed commissions

Read [intent and script development](../../references/intent-and-script-development.md). A detailed supplied
draft is not automatically approved copy: extract the message, required phrases and intended framework,
then strengthen the script and picture relationship. Keep retained source speech and explicit exact-copy
requirements intact. Use an approved version requested unchanged as the execution authority. Fix or flag a conflict with duration, factual evidence, or pronunciation without silently rewriting the proposition. If the user supplies only a product, investigate what it does and what the intended audience needs before choosing an angle.

Build a small claim/evidence ledger: proposed claim, supporting product state or source, uncertainty, and the visual evidence that could make it believable. Do not invent performance numbers, customer endorsements, prices, or completed results. Separate a demonstrated capability from an illustrative workflow.

Choose an audience problem, one main promise, an appropriate proof, and a next action. These are questions to answer, not a mandatory four-part script. A skeptical comparison, anecdote, tutorial, demonstration, dialogue, or concise announcement may better fit the reference. Let the reference inform the rhetorical moves and sentence character without transplanting claims about another product.

Write speech for a mouth: clear phrases, natural transitions, manageable clauses, and a recognizable point of view. Mark difficult brand/product pronunciations. Estimate speaking duration only for planning; final timing comes from the actual recording. Leave enough room for a viewer to read or perceive the demonstration.

Develop the script and picture plan together. Each important passage should have an intended visual responsibility: the person carries conviction, a real UI demonstrates a step, a comparison organizes evidence, or B-roll supplies context. It is valid to remain on the presenter when no additional picture helps. Do not add a generic visual on every sentence.

For ambiguous product positioning or a newly developed message with meaningful tradeoffs, share a concise angle and script for the user's input. Existing instructions can already authorize proceeding; do not create a mandatory approval gate for every draft, shot, or retry. Record accepted content and change only the requested scope in later revisions.

Hand off the script with stable passage names and meaningful event labels. Distinguish narration to be heard, text to be displayed, pronunciation hints, and visual direction. The generated performance prompt should not accidentally speak stage directions or request the product UI to materialize inside the presenter's room.

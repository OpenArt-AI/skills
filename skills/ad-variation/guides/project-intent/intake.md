# Intake and presenter onboarding

Read the supplied material first. A useful intake establishes the desired result, audience, platform/aspect ratio, spoken language, and what must remain unchanged. Infer obvious answers from the request and existing project; record assumptions that materially affect the video. Do not require a product, reference, B-roll, or generated presenter when the commission does not need one.

Classify assets by purpose:

| Role | What it supplies | What it does not automatically supply |
| --- | --- | --- |
| Retained recording | Actual picture, sound, takes, and duration for editing | Permission to replace the performance with AI |
| Identity/performance reference | The intended person's appearance and, for video, manner of speaking and moving | The new script or the old video's graphic design |
| Creative reference | Argument, pacing, editing, framing, visual systems, and tone | The target person's identity or new product's claims |
| Product evidence | Real appearance, UI states, supported claims, brand assets | An invented result, testimonial, or account action |

For a real person to be generated, guide the user toward useful inputs in this order:

1. Reuse an existing clear recording of that person speaking toward the camera. Inspect the useful range, face visibility, delivery, and audio first.
2. If unavailable, suggest a short natural phone-camera recording: face visible, even light, quiet room, ordinary expressions and gestures, no beauty filter, and enough framing for the intended shot. Choose the upload excerpt after inspecting the selected model's reference limits; do not prescribe a universal model duration.
3. If recording is impractical, request real face photos, preferably front and oblique views with consistent appearance. Explain that photos supply appearance but not continuous gesture, delivery, or vocal manner. A model's video-reference field cannot be replaced by prose claiming a video was supplied.

Use appropriate supplied material without making the user record again. If no identity is intended, cast a fictional presenter through image/video direction instead of demanding personal uploads. If a model cannot accept the useful reference, surface that capability mismatch and resolve the choice rather than silently dropping the reference.

For a software promotion, obtain the actual product URL and inspect its interface; a landing page may support claims, but it is not a substitute for the product's UI. Ask for access or a relevant supplied capture only when the required state is inaccessible. See [product interface](../creative-direction/techniques/product-interface.md).

Clarify decisions, not implementation trivia. Useful questions include whether a strict replacement should preserve original audio, whether an unverified claim is factual, and which missing presenter asset the user can provide. Avoid asking again about accepted scripts, selected accounts, models, or spending already authorized within this commission. Record that scope in the project brief.

# A resumable production

Keep task notes and receipts in the conversation or a user-requested document. When the host offers file storage, create or locate one production directory outside the installed plugin; the production owns this video's files. Local filesystem access is optional for notes. Do not store credentials, user media, generated results, or project-specific design choices inside the installed Skill.

Keep these responsibilities visible, combining documents for a small job:

- **Brief:** goal, audience, deliverables, supplied inputs and their roles, constraints, accepted choices, paid scope.
- **Reference analysis:** the whole-piece reading, observed evidence, uncertainty, and the relationships worth preserving.
- **Event ledger:** source ranges, words/actions, picture states, entrances/exits, sound, and why a change matters.
- **Treatment:** the new argument, performance direction, visual organization, retained/generated/authored material, and adaptation choices.
- **Progress:** current source/run, accepted asset IDs, active jobs/builds, unresolved issues, next action.

Use a simple task folder for the source files, accepted outputs and brief working notes. Keep only records useful for the requested edit or resuming generation; no component, runtime or editable-project directory structure is required.

For each material record: original path or URL, purpose, selected range, upload/reference IDs when relevant, generation receipt, accepted/rejected state, local path, and any crop/trim/retime. Keep personal media and account-specific evidence out of public example bundles.

On continuation, inspect Progress, the current run, accessible outputs, and remote receipts before submitting anything. A missing final export does not imply the presenter was never generated. An interrupted observer does not prove a job stopped. Carry forward accepted assets even if a later stage failed.

Record decisions that cannot be recovered from filenames, such as chosen source ranges and which output was accepted. A short note and timing data are sufficient; do not create an engineering handoff or rebuild package.

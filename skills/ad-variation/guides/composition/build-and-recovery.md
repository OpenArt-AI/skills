# Execution and recovery

Before execution, inspect what the proposed operation will actually produce and what existing material
it will reuse. A caption or graphic revision should not introduce a new presenter generation. Preserve
the approved version, output count, model mode and spending scope. Resolve accidental regeneration first.

Record actual operation identifiers and outcomes as soon as they are available. Keep planned, submitted,
running, succeeded and failed work separate from accepted, rejected or unreviewed material. An observation
timeout is not a failed job. Reconcile active work and existing results before submitting again.

Preserve accepted intermediates even when a later operation fails. A retry should address the identified
failure and retain unaffected material. Select exact files or outputs explicitly; repeating a request does
not itself guarantee reuse. Changed takes invalidate their dependent alignment, captions and event timing.

Use bounded observations and share meaningful progress during long work. If no receipt was returned,
reconcile available local or remote operations by project, time, inputs and status. Do not create duplicate
paid generations to resolve an unknown outcome. Stop repeated failures without a useful correction.

A focused range preview can help diagnose a difficult passage but does not replace full-export review.
Check whether it would trigger upstream generation before using it. Cancel only superseded work belonging
to this production when needed, preserving unrelated active work. Retain failure evidence and the corrected
plan so the next agent can resume. Deliver actual complete outputs with honest review status.

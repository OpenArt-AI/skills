# Direct still material

Before prompting, name the image's job: identity anchor, product reference, scene establishment, supporting evidence, or a designed visual asset. Existing accurate material may serve the job better than a new image. Use actual product/UI assets for factual interface content.

Build the prompt around visible decisions: subject and identity relationship, action or pose, setting, framing, camera character, light, materials, and the details that must remain accurate. Tie style words to the intended image. A candid phone-camera look can involve ordinary available light, close conversational framing, and restrained processing; adding "cinematic" may contradict that treatment.

When a photo anchors a later speaking shot, compose for a plausible performance: eyes and mouth visible, crop suited to gestures, stable identity, and no unnecessary objects that constrain animation. If the user supplied real-person references, explicitly identify which upload owns the person's appearance. Multiple references need roles rather than an undifferentiated instruction to combine them.

Choose high-value details instead of an adjective inventory. Request only the elements this image must contain. Exact labels, captions, and product UI are usually authored or captured later for correctness; do not rely on a model to produce interface typography merely because it can generate convincing screens.

Before submission, inspect the live model form for supported image inputs, reference count, output size, and prompt controls. Preserve the authored prompt and references in the receipt. After generation, inspect the result at useful scale, including identity/product details that later crops reveal. An image selected for continuity becomes a specific accepted asset, not an implicit style instruction.

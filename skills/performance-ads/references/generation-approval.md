# Review the plan and choose how to generate

Read [shared video experience](video-experience.md). Complete the full prompt and matching Script Plan
before requesting a generation decision. This applies to each video/variant, not only to sparse briefs.
Apply [intent and script development](intent-and-script-development.md) even to complete supplied drafts.
Preserve explicit exact-copy constraints and reuse approvals already granted for the same unchanged scope.
Pasting a full script is not approval of that script. When changing supplied creative input, apply the
mandatory disclosure and version-choice step below before generation.

## End a revised-script response with disclosure and a real choice

Whenever the proposed Script Plan changes the user's supplied wording, creative structure, actions,
screen text or beat timing, END the response containing the plan with a short change explanation and
an explicit question: use the improved version, or follow the original input exactly?
This is required, not an optional editorial note. Put it in the actual response, not only in an attached
plan, internal record or hidden prompt. State what changed and why in one or two sentences; mention the
important information retained when useful. Do not disparage the original draft or guarantee better results.

Standard wording, translated naturally into the user's language:

"I kept [required information/framework] and changed [specific wording/action/timing] to [creative reason].
Would you like to proceed with this revised script, or follow your original input exactly?"

Example for the lamp draft:

"I kept the touch-dimming feature, $29 price and six-second length, and turned the three feature labels
into a question, demonstration and reaction so it feels like a natural recommendation.
Would you like to use this version, or follow your original script exactly?"

Use the native choice UI when permitted, with both meaningful choices visible: "Use the revised script"
and "Follow my original input exactly"; the user may also request further edits. Keep the closing disclosure
and question in the response even when a native control carries the answer. For approval-capable controls,
these choices may also explicitly approve generation in the shown mode and spending scope. State that
effect clearly; a preference-only control cannot silently authorize paid generation.

Wait for a real answer before generating the rewritten content. Do not infer acceptance from silence,
a preselected option, a quality-mode choice, or the fact that the agent considers its script stronger.
A generic earlier approval waiver does not by itself choose between a newly rewritten draft and the original.
Reuse an explicit version choice already made for the same revision; do not repeatedly ask it.
If the user specifically delegates this version choice and waives further review, retain the disclosure
and respect that instruction within scope rather than manufacturing another approval loop.

If they choose the revised script, bind execution to that displayed prompt/plan version. If they choose
the original, restore its requested wording, actions and timing constraints and prepare the corresponding
full prompt and readable plan; do not retain hidden improvements. Reuse clear generation authorization
for that original-input scope. If it cannot be executed faithfully, explain the concrete conflict rather
than claiming exact compliance. Choosing the original does not guarantee model-level timing or fidelity.

Keep script-version choice separate from Draft/full-quality choice. Bundle the decisions in one review
when useful, preserving the existing mode default or user selection. Do not offer only "generate preview"
and "generate full quality" when the user's original has been rewritten: both omit the required version choice.
For genuinely unchanged execution or new writing from a factual brief with no supplied creative script,
use normal plan review; do not claim to have rewritten a nonexistent original. Changed creative direction
inside a brief still requires disclosure. Exact-wording and timing constraints remain binding during drafting.

## Use the host's native question interface when permitted

Prefer the host's native question/choice UI for missing preferences and for approval when that tool explicitly
permits approval requests. Inspect current tool instructions: names, availability and modes vary by host.
Never switch modes merely to obtain a question tool. A preference-only or clarification-only tool must not
be repurposed as a paid-generation approval gate. If native approval is unsupported, show the same concise
choices in chat and wait for the user's response. A preselected option is not a submitted answer.

Show the Script Plan in the conversation or an accessible artifact before the choice, so approval refers
to a concrete version. Bundle relevant settings rather than asking repeatedly about model, ratio and script.
When the approval question UI supports it, use these stable meanings and translate naturally into the
user's language. Fill actual counts, supported resolutions and estimated credits before presenting them.

### Standard preview-first wording

"The plan is ready. Unless you prefer a full-quality render, we will start with a Seedance 2.5 Draft preview
to review the performance, product and pacing at lower resolution and lower upfront cost than HD.
If you like it, you can approve the available HD upgrade afterward. How would you like to proceed?"

- "Approve and generate a preview (Recommended)" — use Seedance 2.5 Draft for the shown scope.
- "Approve and generate full quality" — use Seedance 2.5 at the shown supported HD resolution and price.
- "Revise the plan first" — change the paired prompt and plan; do not generate yet.

Use the lower-cost comparison only after checking actual configuration pricing. If unavailable, say
"start with a lower-resolution preview" and explicitly leave the credit estimate unavailable.
If the user approves generation without choosing a mode, use the stated Draft default; do not ask again.

### When high-quality delivery is already requested

"You asked for a high-quality final video, so this plan uses Seedance 2.5 directly at [resolution].
Generate [count] video(s) from this plan for approximately [credits] credits, or revise the plan first?"

Do not present Draft as the recommended selection when the user already chose direct high-quality output.
Do not ask again when an existing authorization already covers the displayed plan and generation scope.

### After a preview

"This is the [actual resolution] preview. You can revise it, or approve upgrading this selected video
to [offered resolution] for [quoted additional credits] credits. This upgrade is available until [expiry]."

Offer "Upgrade this preview to HD" and "Revise the preview" when both are available. Omit unsupported
upgrade promises; explain missing eligibility or price. Use a supported approval channel for the paid choice.

## Authorization and scope

An explicit "skip approval and generate" instruction is authorization within its stated scope, subject to
the revised-script version-choice rule above. Complete
the prompt/plan internally, communicate the selected mode and proceed without an artificial confirmation
loop. A high-quality preference alone is not approval of a newly authored creative plan. Silence and elapsed
time are neither generation nor upgrade approval. Reuse settled choices, but never expand one approved
video into additional variants, image dependencies or unlimited retries without authorization.

Record the response, prompt/plan version, quality mode, ratio, duration, output/request counts, reference
roles and allowed retries. A material creative or spending change must be resolved before affected jobs.
Defaulting to Draft selects a mode; it does not itself authorize payment.

## Fit the plan to natural delivery

Read exact dialogue at the intended pace, allowing meaningful handling, pauses and a complete ending.
Keep screen-reading time separate from spoken duration. Fit a supported duration to the substance; when
duration is fixed, preserve locked copy and resolve a real mismatch rather than rushing or dropping words.
Timed plan rows can describe one continuous shot; they do not require cuts or separate paid requests.
